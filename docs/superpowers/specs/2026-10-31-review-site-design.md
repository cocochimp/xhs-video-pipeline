# 审片网站 — 设计

日期：2026-10-31
状态：已确认（2026-10-31）

## 目标

现在每期视频是整条生成，哪里不满意就得整条重跑。审片网站把一期拆成切片：用户逐片看、用一句话描述问题，AI 只改这一片，用户再看，满意就通过。全部通过后一键渲染整期。

只给一个人用，运行在本机 Mac 上。

## 已确定的决策

| 项 | 决定 |
|---|---|
| 页面形式 | 分镜表式：左侧切片卡片列表，右侧固定预览和工作区 |
| 修改方式 | 只由 AI 修改。用户只写问题，不直接编辑台词、素材或时间 |
| AI 执行方式 | 网站后端在后台调用本机 Claude Code（`claude -p`），不另配 Anthropic API key |
| 技术方案 | Node 后端 + React 前端，前端内嵌 `@remotion/player` 实时预览 |
| 配音粒度 | 改了一句台词，就重配这句所在的整段配音 |
| 切片粒度 | 一个切片 = 一个场景（一屏画面，可包含多句台词）。第 1 期共 10 片 |
| 部署 | 本机运行，浏览器打开 `http://localhost:4100` |
| 新建一期 | 四步，每步用户通过才进入下一步：① 选题 → ② 文本 → ③ 生成视频 → ④ 审片 |
| 文本阶段的画面说明 | 每个场景一两句话的大意，不写到素材和动作级别 |

## 不在第一版范围内

- 背景音乐和音效的管理界面（继续用 `opening/make_audio.py` 的占位音乐和自动音效）
- 网页里直接拖拽或编辑台词、素材、时间
- 素材库的上传、编辑、重画（第一版只读浏览）
- 云端部署、多人使用、手机端访问

## 1. 目录和数据

```
xhs-video-pipeline/
  studio/                 网站代码（前端 + 后端）
  shared/                 公共组件：Pose、Sticker、Card、BigText、Check、Strike、Paper、TopBar、Subtitles
  assets/                 素材（由 aniu/public 迁移）：pose_*.png、prop_*.png、avatar.jpg
  episodes/ep001/
    episode.json          本期唯一数据源
    scenes/s01.tsx … s10.tsx   每片一个场景文件
    audio/                vo_<段>.mp3 + timeline.json（配音生成，不手改）
    history/s07/r1/       每轮修改前的备份
    out/                  成片、缩略图
  tts_doubao.py, pipeline.py, opening/make_audio.py   沿用
```

### episode.json

```json
{
  "no": 1, "total": 100,
  "stage": "review",
  "topic": {"candidates": [{"title": "...", "hook": "...", "number": "150万"}], "chosen": 0, "rounds": []},
  "title": "月薪8千，想退休到底要攒多少钱？",
  "roll": ["应急金存几个月才够？", "..."],
  "segments": [{"id": "body", "gap": 0.5}],
  "scenes": [
    {
      "id": "s07", "name": "150万", "segment": "body",
      "visual": "150万砸下来，阿牛受惊，旁边一个钱袋",
      "lines": [{"zh": "每月5000，一年【6万】", "say": "每月五千，一年六万，"}],
      "textStatus": "approved",
      "status": "pending",
      "rounds": [{"n": 1, "issue": "数字太小", "summary": "150万字号 200→240，加画面震动", "cost": 0, "at": "2026-10-31T14:02:00"}]
    }
  ],
  "cost": {"tts": 0.08, "image": 0}
}
```

- 配音音色和语速是全局配置，写在 `studio/config.json`（`{"voice": {"speaker": "zh_male_wennuanahu_uranus_bigtts", "rate": 15}}`），所有期数共用，不放进 `episode.json`。AI 改片时不能改这个文件。每期在 `audio/timeline.json` 里记下配音时用的音色和语速；全局配置改了以后，配音不一致的期数在首页和单期页顶栏显示「配音音色已变更，可重配」提示，点了才重配，不自动重配。
- `stage` 取值：`topic` 选题、`text` 文本、`generating` 生成中、`review` 审片、`done` 已完成。
- `visual` 是文本阶段写的画面大意，第 ③ 步生成场景代码时按它来画。
- `textStatus` 是文本阶段每个场景的审核状态（`pending` / `working` / `approved`），`status` 是审片阶段的状态，两者分开。
- `zh` 是字幕显示文本，`【】`里的字标橙色；`say` 是朗读文本（数字写成汉字）。
- `status` 取值：`pending` 待审、`queued` 排队中、`working` AI 修改中、`approved` 已通过、`asking` 待你回复、`error` 出错。
- 一个配音段（`segment`）由连续的若干场景组成，配音按段整段合成。

### 场景文件接口

每个场景文件默认导出一个组件，只接收相对时间：

```ts
type SceneProps = {
  at: (i: number) => number;   // 本片第 i 句台词开始的帧，相对本片开头
  dur: number;                 // 本片总帧数
};
```

场景代码不写绝对秒数。配音变化后，所有切片的起止时间由 `audio/timeline.json` 重新计算，后面的切片自动顺延，场景文件不用改。

## 2. 页面

**首页**：列出所有期数（期号、标题、当前阶段、通过进度、花费）、「新建一期」按钮、素材库入口（只读，显示每个素材的名字，方便写问题时引用）。

**单期页**：
- 顶栏：期号和标题、通过进度（如 6/10）、本期累计花费、「渲染整期」按钮（全部通过才能点）、「强制渲染草稿」。
- 左侧：切片卡片列表。每张卡显示缩略图、片名、时长、前一两句台词、素材、状态。已通过的卡变淡。
- 右侧：选中切片的工作区。
  - 预览：默认只播本片，前后各带 0.5 秒；可切换整期播放。
  - 问题输入框 +「交给 AI 修改」「通过」两个按钮。
  - 修改记录：每轮显示你的问题和 AI 的修改说明，每条可「撤销到此前」。
- 提交后不用等待，可以继续审别的片。AI 改完，卡片变回「待审」并标「已更新」。

**新建一期**：分四步，每步通过后才进入下一步。前两步只有文字，不配音、不生图，不花钱。

| 步骤 | AI 做什么 | 用户做什么 |
|---|---|---|
| ① 选题 | 参考 `docs/选题库.md`，避开已使用的选题，给出 5 个候选（标题、一句话钩子、核心数字） | 选一个通过；或写意见（如「换一批」「第 3 个标题更扎心」），AI 重新给 5 个 |
| ② 文本 | 按选题写脚本：拆成场景，每个场景写台词（`zh` + `say`）和一两句画面大意（`visual`） | 逐场景看，写问题，AI 只改那个场景的文字；可撤销。全部场景通过后点「通过脚本」 |
| ③ 生成视频 | 整期配音 → 逐个生成场景文件 → 缺的素材用 flash 补 → 类型检查和截图检查 | 等待；页面显示进度（如「配音完成 → 场景 4/10 → 检查中」）。某个场景生成失败，标 ⚠️出错，其余照常，进入审片后再改 |
| ④ 审片 | 第 3 节的逐片修改流程 | 逐片审，全部通过后渲染整期 |

- 选题通过后，在 `docs/选题库.md` 里把它标为「已使用」。
- 进入第 ③ 步后脚本锁定；审片时如果要改台词，按第 3 节「改了台词」的规则只重配那一段。
- 第 ① ② 步的 AI 任务和审片修改共用同一个任务队列，一次只跑一个。

## 3. AI 修改一片的流程

后端维护一个任务队列（持久化到 `studio/jobs.json`，重启不丢），**一次只执行一个任务**。

1. **备份**：把 `scenes/s07.tsx` 和 `episode.json` 复制到 `history/s07/r<轮次>/`。
2. **调用 Claude Code**：`claude -p`，工作目录为本期目录，传入：
   - 用户写的问题
   - 本片场景代码、台词、在 `timeline.json` 里的时间
   - 素材清单
   - 固定的改片规则文件 `studio/rules.md`（可改什么、不可改什么、怎么重配音、怎么生成新素材）
3. **限制改动范围**：允许修改的只有 `scenes/s07.tsx` 和 `episode.json` 中本片的 `lines`。重配音、生图只能通过 `studio/tools/` 下的脚本完成。后端在任务前后对本期目录、`shared/`、`assets/` 做文件哈希对比，发现越界改动就作废本轮并还原。
4. **自动检查**：类型检查，再渲染本片中间一帧（这张图同时作为新缩略图）。失败时把错误交回 Claude Code 重试一次；仍失败则还原，状态设为 `error`，修改记录写明原因。
5. **成功**：状态回到 `pending`，标「已更新」，修改记录写入 AI 的一两句修改说明和本轮花费。

### 特殊情况

| 情况 | 处理 |
|---|---|
| 改了台词 | `tools/revoice <段>` 重配整段，重算 `timeline.json`，后面切片自动顺延。已通过的切片保持通过；同一段里其他已通过的切片，因为配音重新合成过，卡片加「配音已更新」提示，不改状态 |
| 需要新素材 | `tools/gen_asset` 用 Seedream flash 生成并抠图（0.12 元/张），新素材进 `assets/`，费用记入本期 `cost.image` |
| 单次修改费用超过 1 元 | 照常执行，不暂停。修改记录里这一轮标红显示花费，卡片上加「本轮花费 ¥x」提示 |
| 问题太模糊 | AI 不修改，写一条提问，状态设为 `asking` |
| 运行超过 5 分钟 | 中止进程，还原，状态设为 `error` |

撤销：把选中轮次的备份拷回，之后的轮次标记为已撤销（保留记录）。若撤销涉及台词，同时重配该段。

## 4. 渲染整期

全部切片通过后点「渲染整期」：Remotion 渲染整片 → `opening/make_audio.py` 混入占位背景音乐和音效 → 输出 `episodes/ep001/out/ep001.mp4`。「强制渲染草稿」流程相同，文件名加 `-draft`。

## 5. 启动方式

在项目根目录运行 `npm run studio`（或双击 `studio/start.command`），启动后端和前端，自动打开浏览器。前端用 Vite，场景文件被 AI 修改后通过热更新直接刷新预览，不需要先渲染视频。

## 6. 迁移

把现有第 1 期迁移到新结构：`episode/src/Body.tsx` 的 7 个场景拆成 `s03`–`s09`，开头、选题滚动、结尾分别为 `s01`、`s02`、`s10`；`episode/make_timeline.py` 里的台词搬进 `episode.json`；公共组件搬进 `shared/`。迁移后渲染出的整片应与现在的 `episode/out/ep1.mp4` 画面一致。

## 7. 测试

1. 迁移后的第 1 期整片与旧版逐场景截图对比一致。
2. 三类修改各跑一次：只改动画（如「150万砸下来慢一点」）、改台词需要重配音、需要生成新姿势。
3. 越界测试：问题里故意要求「顺便把第 5 片也改了」，确认越界改动被拦下并还原。
4. 撤销测试：连续改两轮后撤销到第 1 轮前，场景文件和配音都恢复。
5. 超时和费用提醒：用模拟任务验证 5 分钟中止，以及单轮花费超过 1 元时修改继续完成、记录标红。
